# MapToLearn 批量生成与数据库导出设计

## 目标

为 Web 版 MapToLearn 增加两种后台批量生成入口，并将已生成的学习内容安全导出为 SQLite 数据库：

- 首页可对应用内全部书籍按顺序、按小节生成卡片。
- 书籍详情页可只对当前书籍生成全部剩余小节。
- 生成期间用户可以继续浏览、阅读和播放语音。
- 首页可导出完整应用数据库；书籍详情页可导出仅含该书的数据。
- 书籍详情中的卡片摘要可点击并直接定位到阅读器中的对应卡片。

本功能只使用用户已配置的 DeepSeek 服务生成内容。离线阅读指已生成卡片继续保存在本地 SQLite 中，不依赖网络或 DeepSeek；尚未生成的小节无法离线生成。

## 用户界面与行为

### 首页

首页书库区域增加两个带说明文字的操作：

- `生成全部书籍`：将当前应用内仍有待处理小节的书籍按创建时间加入单一后台队列。已有卡片不会删除，任务从每本书的 `generation_cursor` 继续。
- `导出全部应用数据库 (.db)`：下载当前应用 `app.db` 的一致性快照，包含全部书籍、知识卡片、收藏状态和追问记录。

当队列运行时，首页显示当前书名、当前小节、已处理小节数、总小节数、已新增卡片数与状态。按钮切换为 `暂停生成`；暂停后显示 `继续生成`。同一时刻只允许一个后台队列，避免多个 DeepSeek 请求互相抢占并拖慢阅读和 TTS。

### 书籍详情页

书籍详情页增加：

- `生成本书全部小节`：仅将当前书籍的剩余小节加入同一后台队列。
- `导出本书数据库 (.db)`：下载独立 SQLite 文件，只含当前 `Book`、其 `ConceptCard`、收藏状态和关联 `ChatMessage`。

已有的 `继续生成` 保留为“只处理下一个小节”的即时操作，`从头生成` 保留为删除本书旧卡片后重新开始的显式操作。后台批量按钮默认不删除已有数据。

卡片摘要改为按钮：点击任何摘要后，阅读器用目标 `cardId` 打开该卡片。未点击摘要而直接点 `开始阅读` 时，继续使用已有的上次阅读位置恢复规则。

### 阅读器

阅读器新增可选 `targetCardId` 导航参数。若有目标卡片，优先滚动到该卡片；否则按本地保存的 `reader-progress-{bookId}` 恢复。目标定位只对本次进入阅读器生效，不覆盖用户之后的正常阅读进度。

## 后端设计

### 持久化任务

新增 `GenerationJob` 表，表示一个应用级后台队列：

- `scope`：`all_books` 或 `single_book`。
- `book_ids_json`：任务创建瞬间冻结的书籍 ID 顺序。
- `status`：`queued`、`running`、`paused`、`completed`、`failed`。
- `current_book_id`、`current_book_position`、`processed_sections`、`total_sections`、`generated_cards`、`message`、`error` 与时间字段。

应用内的任务管理器只运行一个 `asyncio` worker。worker 每次取一册书、调用现有的单小节生成器、提交卡片和游标，然后刷新 `GenerationJob` 状态。每轮均创建独立数据库 Session，避免长时间持有数据库连接。

停止或重启后，不会回滚已生成的卡片。服务启动时，将遗留的 `queued` 或 `running` 任务标为 `paused`，前端显示为可继续任务。暂停请求在当前正在进行的 DeepSeek 调用结束后生效。

### API

- `POST /api/generation-jobs/all-books`：创建或恢复全部书籍任务。
- `POST /api/books/{book_id}/generation-job`：创建或恢复当前书籍任务。
- `GET /api/generation-jobs/current`：返回当前或最近任务的状态；无任务返回 `null`。
- `POST /api/generation-jobs/{job_id}/pause`：请求暂停。
- `POST /api/generation-jobs/{job_id}/resume`：恢复暂停任务。
- `GET /api/exports/app-database`：下载完整应用 SQLite 快照。
- `GET /api/books/{book_id}/export-database`：下载当前书籍的独立 SQLite 数据库。

创建任务时若已有运行或暂停任务，接口返回该任务而不是创建并发队列。前端使用短轮询刷新进度，不使用长连接或页面阻塞等待。

### 数据库导出

完整应用导出使用 SQLite backup API 创建临时快照，避免复制正在写入的 `app.db` 文件导致不完整导出。单本书导出创建新的 SQLite 文件和当前项目的表结构，只复制指定书籍、其卡片和追问记录；不会复制其他书籍、运行时设置、API Key、语音缓存或模型文件。

下载完成后删除临时导出文件。导出目录被 Git 忽略。

## 前端数据流

`UploadPage` 负责首页任务入口及全局导出。`BookPage` 负责单书任务、单书导出和卡片摘要导航。二者使用同一组 API 客户端方法和同一份任务状态对象。

任务运行时页面每 1.5 秒查询一次状态。书籍详情页发现当前书的 `generation_cursor` 或卡片数变化时刷新书籍与卡片列表；首页同步刷新书库计数。页面卸载时停止轮询，不停止服务器任务。

## 错误处理

- DeepSeek 未配置、网络异常或上游返回错误：任务转为 `failed`，保留已生成内容、游标和错误信息；用户可从当前位置重新启动。
- 当前书无剩余小节：任务直接完成并显示“无待生成内容”。
- 导出失败：返回 JSON 错误，不影响本地数据库和后台任务。
- 目标卡片已经不存在：阅读器回退到上次阅读位置。

## 测试与验收

- 后端：验证单书任务按游标逐节写卡片、全书任务顺序、暂停/恢复、重启遗留任务处理，以及两种数据库导出的数据范围。
- 前端：验证单书/全部按钮调用正确 API、任务进度展示、卡片摘要将目标 cardId 传入阅读器、普通开始阅读仍使用保存进度。
- 回归：运行后端 pytest、Vite 构建、安卓既有 Jest 测试。

验收时应确认：用户可启动全局或单书批量生成并继续阅读；生成内容在重启后仍存在；两种 `.db` 导出范围正确；点击摘要从指定卡片进入阅读器；未选择摘要时恢复上次阅读位置。
