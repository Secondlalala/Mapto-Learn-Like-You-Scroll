# MapToLearn 数据库导入与单书删除设计

## 目标

为 Web 版 MapToLearn 增加 SQLite 卡片数据库导入与单书删除能力：

- 首页可导入本项目导出的单书数据库或完整应用数据库。
- 数据库中的每本书都作为新副本导入，不覆盖或合并现有同名书籍。
- 书籍、卡片、收藏状态和追问记录完整迁移，并重新分配本地主键。
- 书籍详情页可删除当前书籍及其全部关联学习数据。
- 将当前 `qft` 导出为独立卡片数据库，并在隔离数据库中完成导入闭环验证。

## 方案比较

### 方案 A：导入为新副本并重新映射主键（采用）

每次导入均创建新的 `Book`，随后建立旧 Book ID 到新 Book ID、旧 Card ID 到新 Card ID 的映射，最后迁移 ChatMessage。优点是不会覆盖现有数据，重复导入可预测，也能可靠处理不同数据库中相同的自增 ID；代价是用户可能得到同名副本，因此需要单书删除功能。

### 方案 B：按书名和文件名自动合并

同名书籍尝试与现有记录合并。它能减少副本，但无法可靠判断两本同名文件是否属于同一版本，也难以决定卡片、收藏和追问冲突的优先级，容易静默污染现有知识体系，因此不采用。

### 方案 C：导入前清空并替换整个应用数据库

实现简单，但会覆盖所有本地书籍和学习记录，且正在运行的 SQLite 连接与后台任务使替换风险更高，不符合用户对回滚和数据保存的要求，因此不采用。

## 导入交互

首页书库操作区增加 `导入卡片数据库 (.db)`。点击后只允许选择 `.db`、`.sqlite` 或 `.sqlite3` 文件。导入期间按钮显示忙碌状态并禁止重复提交；完成后显示导入书籍数、卡片数和追问数，刷新书库，但不自动进入某一本书。

导入接受两种现有导出文件：

- 单书数据库：包含一条 Book 及其 ConceptCard、ChatMessage。
- 完整应用数据库：包含多条 Book；只导入 Book、ConceptCard、ChatMessage，不导入 GenerationJob 或运行时任务状态。

同一个数据库可以重复导入，每次产生独立副本。导入标题保持原书名；书库通过新 ID 区分副本，不擅自改写标题。

## 后端数据流

新增 `POST /api/imports/database`，使用 multipart 表单接收数据库文件，返回：

```json
{
  "imported_book_ids": [2],
  "imported_books": 1,
  "imported_cards": 18,
  "imported_messages": 3,
  "message": "数据库导入成功"
}
```

导入流程：

1. 校验扩展名和上传体积，保存到系统临时目录，不写入书籍 uploads 目录。
2. 使用 SQLite 只读 URI 打开文件，并验证 `books`、`concept_cards`、`chat_messages` 三张表及必需字段。
3. 检查外键语义：每张卡必须属于导入数据库中的书，每条追问必须属于导入数据库中的卡。
4. 在目标数据库开启单个事务，先插入所有 Book 并建立 ID 映射，再插入 ConceptCard 和 ChatMessage。
5. 所有记录成功后一次提交；任意错误整体回滚。
6. 无论成功或失败都关闭上传数据库连接并删除临时文件。

字段复制仅使用当前模型认可的列。导入文件中多余的表和列被忽略；缺少当前模型必需列则返回 `400` JSON 错误。时间字段无法解析时回退到当前时间，JSON 列表字段必须保持合法 JSON 数组，否则该记录的对应列表使用空数组。

数据库默认大小上限为 200 MB，避免把任意大文件加载到本地服务；解析采用逐行读取，不把整库一次性载入内存。

## 删除交互与 API

书籍详情页增加危险样式的 `删除本书数据库` 按钮。点击后打开确认对话框，显示将删除的书名、卡片数和关联追问，并要求用户输入完整书名；输入不匹配时确认按钮不可用。

新增 `DELETE /api/books/{book_id}`，请求体为：

```json
{
  "confirmation_title": "qft"
}
```

后端再次校验书籍存在且书名完全匹配，然后在单个事务内删除该书的 ChatMessage、ConceptCard 和 Book。成功返回删除计数。接口不会删除整个 `app.db`、其他书籍、DeepSeek/TTS 设置、语音缓存或导出的 `.db` 文件。

删除成功后清理该书的浏览器阅读进度并返回首页。若该书正在后台批量任务中，删除接口返回 `409`，要求先暂停或等待任务结束，避免 worker 持有已删除对象。

## 安全与错误处理

- 上传内容不是 SQLite、文件损坏、缺表或缺字段：返回 `400`，目标数据库不写入任何记录。
- 文件超过 200 MB：返回 `413`。
- 导入过程中发生目标数据库错误：整体回滚并返回 `500`。
- 删除确认书名不匹配：返回 `400`。
- 删除目标不存在：返回 `404`。
- 后台任务正在处理目标书：返回 `409`。
- 所有 API 错误继续使用 JSON `detail`，前端直接显示可读中文信息。

## qft 验证产物

从当前真实 `backend/app.db` 的 `qft` 记录生成：

`book-concept-app/exports/qft-card-database.db`

该文件包含 qft 原文、章节切分、生成游标 15、18 张卡片、0 个收藏和 2 条已有追问。`.db` 继续被 Git 忽略，避免把用户书籍内容公开推送到 GitHub。

闭环验证使用临时目标 SQLite，不向真实 `app.db` 重复插入：

1. 导出当前 qft。
2. 将导出文件导入一个空临时数据库。
3. 校验书籍数为 1，卡片数为 18，追问数和收藏数与源数据库一致。
4. 再次导入同一文件，校验书籍数和卡片数翻倍且主键不冲突。
5. 删除其中一个导入副本，校验另一个副本及其卡片保持完整。
